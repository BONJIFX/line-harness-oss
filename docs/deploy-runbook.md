# apps/worker デプロイ手順書

自動デプロイ(`.github/workflows/deploy-worker.yml`)が secrets 未設定等で
動かない間、手動デプロイは必ず本手順に従う。手順を省略した結果として
2026-07-28 に本番が黙って巻き戻る事故が同日 2 度発生した(下記「過去の
事故と教訓」参照)。

## 正式手順

1. **origin/main の最新を取得し、そこから作業する**

   ```bash
   git fetch origin
   git status   # 作業ブランチが origin/main の最新に追従しているか確認
   git log --oneline -1 origin/main
   ```

   デプロイ元のブランチ・コミットが `origin/main` の最新 HEAD と一致して
   いることを確認してからでないと、次の手順へ進まない。

2. **`pnpm --filter worker test` が PASS することを確認する**

   ```bash
   pnpm --filter worker test
   ```

   1 件でも FAIL したまま次の手順(ビルド・デプロイ)へ進んではならない。

3. **`wrangler deploy` でデプロイする**

   ```bash
   pnpm --filter worker run deploy
   ```

   (内部で `vite build && wrangler deploy` が実行される)

4. **readback(デプロイ後の本番確認)**

   デプロイ直後に本番 URL で顧客事実に関わる画面(CSA 申込ページ・利用規約・
   特定商取引法表記など、直近で巻き戻り事故が起きた面)を実機確認し、
   デプロイしたコミットの内容と一致していることを目視で確認する。
   確認せずに「デプロイ完了」と報告しない。

## 禁止事項(2026-07-28 の 2 事故の教訓)

1. **origin/main 最新以外からのデプロイ禁止**

   2026-07-28 夜、`65d5268`(CSA reminder dispatch)が `71e199d`(支店コード
   修正: 誤 `〇一八支店` → 正 `〇九八支店`)を含まない古い枝から
   `origin/main` へ乗り、本番の申込ページ・利用規約・特定商取引法表記の
   支店名・販売事業者名が黙って巻き戻った(是正 = `a8b558c`)。
   デプロイ元のブランチは必ず `origin/main` の最新から派生しているか、
   最新そのものであることを事前に確認する。

2. **未コミット設定でのデプロイ禁止**

   本番環境変数やフラグ(例: リマインド自動送信 ON/OFF)を、コード上に
   コミットせずローカル環境変数や手動設定のみで有効化した状態のまま
   運用しない。次回デプロイ時、コミットされていない設定は git 上の
   (無効化された)状態へ黙って巻き戻る(是正 = `a9448b2`、リマインド
   自動送信 ON を設定ファイルへ恒久化)。**本番の挙動を変える設定は
   必ずコード・設定ファイルへコミットしてからデプロイする。**

## 自動デプロイが動くようになったら

`.github/workflows/deploy-worker.yml` が GitHub 上で正常実行されるように
なった後も、本手順の「原則」(origin/main 最新起点・test PASS 必須・
readback 実施)は workflow 内のステップとして機械化済みだが、
workflow_dispatch での手動実行時や緊急時の直接 `wrangler deploy` を行う
場合は、本手順書を必ず優先して守ること。
